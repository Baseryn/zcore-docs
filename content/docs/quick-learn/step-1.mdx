In this first step, we will set up the foundation of our project. ZCore is designed to be zero-config out of the box, but for a production-ready start, we need to ensure our environment variables and secret keys are generated securely.

<Steps>
  <Step>
    ### Create a Virtual Environment

    Always start by isolating your Python environment. We recommend Python 3.11 or higher.

    ```bash
    python -m venv venv
    source venv/bin/activate  # On Windows use: venv\Scripts\activate
    ```
  </Step>

  <Step>
    ### Install the Framework

    Install ZCore with all its standard dependencies (FastAPI, SQLAlchemy, Pydantic, etc.). The `[all]` flag ensures you get the complete toolkit.

    ```bash
    pip install fastapi-zcore-framework[all]
    ```
  </Step>

  <Step>
    ### Scaffold the Project

    Use the ZCore CLI to generate a clean project structure. Let's call our project `task_manager`.

    ```bash
    zc init task_manager && cd task_manager
    ```

    This generates a minimal FastAPI entry point and a `.env` file.
    <Files>
      <File name="task_manager" />
      <File name=".env" />
      <File name="main.py" />
      <File name="requirements.txt" />
    </Files>
  </Step>

  <Step>
    ### Generate a Secure Secret Key

    <Callout type="warning" title="Security Best Practice">
      By default, the scaffolded `.env` file contains a fallback `SECRET_KEY`. In any environment outside local testing, this **must** be replaced with a cryptographically secure string.
    </Callout>

    ZCore provides a built-in CLI command to generate a secure 64-character hex string. Run this command and copy the output:

    ```bash
    zc gensecret
    # Output example: 🔑 Generated Cryptographic Secret Key:
    # 9f8a2b... (64 characters)
    ```

    Now, open your `.env` file and replace the `SECRET_KEY` value with the generated string.
  </Step>

  <Step>
    ### Understand the Settings Class

    Open `main.py`. You will see that ZCore imports `settings` from `zcore.config`. This `settings` object is a `SettingsProxy` that reads from your `.env` file using Pydantic v2.

    ```python
    # main.py (excerpt)
    from zcore import settings

    # ZCore reads DATABASE_URL, SECRET_KEY, etc., automatically
    print(settings.PROJECT_NAME) 
    ```

    <Callout type="info" emoji="💡">
      **Deep Dive:** The `settings` object is a Proxy. This means importing it at the top of your files is completely safe and doesn't trigger premature initialization of the Dependency Injection container. Values are resolved lazily when accessed.
    </Callout>
  </Step>
</Steps>

Excellent! Your environment is now secure and ready. In the next step, we will initialize the database engine.
