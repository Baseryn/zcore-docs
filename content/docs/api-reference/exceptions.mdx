ZCore provides a unified exception hierarchy mapped directly to standard HTTP status codes. When raised anywhere in your services, repositories, or schemas, these exceptions are intercepted by `app_exception_handler` and converted into consistent, structured JSON responses wrapped in `ResponseWrapper`.

## Base Class: `AppException`

The root runtime exception for all business and domain errors in ZCore.

```python
from zcore.exceptions import AppException

class AppException(Exception):
    status_code: int = 500

    def __init__(self, message: str, payload: Optional[dict] = None) -> None:
        super().__init__(message)
        self.message = message
        self.payload = payload
```

ZCore provides pre-configured domain exceptions mapped to standard HTTP status codes:

```python

    EntityNotFound,
```

## Global Exception Handler: `app_exception_handler`

Asynchronous handler configured on the root FastAPI application instance. It intercepts any `AppException`, logs structured diagnostics via `structlog`, and returns a `ZCoreJSONResponse`.

```python
from zcore.exceptions import AppException, app_exception_handler

app.add_exception_handler(AppException, app_exception_handler)
```

## Standardized JSON Error Response

Every intercepted exception is rendered in the unified `ResponseWrapper` envelope:

```json
{
  "success": false,
  "message": "Task not found.",
  "data": null,
  "meta": {
    "error_type": "EntityNotFound",
    "payload": {
      "task_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
    }
  }
}
```

<Callout type="info" emoji="🪵">
  **Structured Diagnostic Logging:**
  Whenever an `AppException` is caught, `app_exception_handler` automatically logs a structured warning containing the exception type, message, payload, HTTP method, URL path, and request correlation ID (`request_id`).
</Callout>
